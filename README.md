# Resale Radar — Telegram-бот для поиска выгодных предложений

Бот отслеживает нормализованный поток объявлений, сравнивает цену покупки с заданной или
рассчитанной ценой быстрой перепродажи, вычитает комиссию и прочие расходы и уведомляет
только тогда, когда проходят одновременно пороги чистой прибыли и ROI.

Основное управление работает через адаптивное Telegram Mini App: в нём можно создавать и
удалять фильтры, смотреть статистику и вручную проверять найденные объявления. Данные API
доступны только после проверки подписанных Telegram `initData`.

## Что уже умеет

- несколько фильтров поиска на пользователя;
- ручная цена перепродажи или консервативная автооценка по накопленным аналогам;
- учёт процента комиссии и фиксированных расходов;
- защита от повторных уведомлений;
- ограничение доступа по Telegram user ID;
- защищённое Telegram Mini App без отдельных логинов и паролей;
- круглосуточный Cloudflare Worker и база Cloudflare D1;
- SQLite без отдельного сервера;
- загрузка объявлений из любого разрешённого JSON-feed;
- Docker и локальный запуск.

Бот не покупает товар сам и не гарантирует прибыль. Перед сделкой проверяйте состояние,
серийный номер, документы, комплектность и личность продавца.

## Быстрый запуск

1. Создайте бота через `@BotFather` и получите токен.
2. Установите Python 3.11+.
3. В папке проекта выполните:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
Copy-Item .env.example .env
```

4. В `.env` вставьте `BOT_TOKEN`. Чтобы бот был личным, узнайте свой Telegram user ID
   (например, через `@userinfobot`) и укажите `ALLOWED_USER_IDS=123456789`.
5. Запустите:

```powershell
resale-radar
```

Либо через Docker:

```powershell
Copy-Item .env.example .env
# заполните .env
docker compose up -d --build
```

## Бесплатная работа 24/7 через GitHub

GitHub хранит исходники и автоматически выполняет деплой, а круглосуточный Telegram-webhook
работает на бесплатном Cloudflare Worker. Это надёжнее попытки держать процесс внутри
GitHub Actions: GitHub-hosted job ограничен шестью часами, а запуск по расписанию может
задерживаться или пропускаться.

Serverless-версия находится в `worker/` и использует Cloudflare D1 вместо локального SQLite.
Она поддерживает те же основные команды `/watch`, `/watches`, `/delwatch`, `/add`, а
разрешённый JSON-feed проверяется каждые пять минут.

### 1. Создайте бесплатные аккаунты

- GitHub: <https://github.com/signup>
- Cloudflare: <https://dash.cloudflare.com/sign-up>

Банковская карта для бесплатного Workers-плана не нужна. Лимита 100 000 запросов в сутки
и бесплатной квоты D1 для личного Telegram-бота обычно более чем достаточно.

### 2. Один раз создайте базу D1

Из корня проекта:

```powershell
npx wrangler@4 login
npx wrangler@4 d1 create resale-radar
```

Команда напечатает `database_id`. Вставьте его вместо
`REPLACE_WITH_D1_DATABASE_ID` в `worker/wrangler.toml`.

### 3. Создайте API-токен Cloudflare

В Cloudflare откройте **My Profile → API Tokens → Create Token**, выберите шаблон
**Edit Cloudflare Workers** и ограничьте токен своим аккаунтом. Account ID виден на
главной странице Workers & Pages.

### 4. Создайте GitHub-репозиторий и секреты

Создайте пустой репозиторий, затем из папки проекта выполните:

```powershell
git add .
git commit -m "Add resale radar Telegram bot"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/resale-radar-bot.git
git push -u origin main
```

В репозитории откройте **Settings → Secrets and variables → Actions → New repository
secret** и добавьте:

| Secret | Значение |
|---|---|
| `BOT_TOKEN` | токен от `@BotFather` |
| `CLOUDFLARE_API_TOKEN` | API-токен Cloudflare |
| `CLOUDFLARE_ACCOUNT_ID` | ID аккаунта Cloudflare |
| `TELEGRAM_WEBHOOK_SECRET` | случайная строка длиной 32+ символа |
| `WORKER_URL` | адрес вида `https://resale-radar-bot.ВАШ-SUBDOMAIN.workers.dev` без `/` в конце |

Затем на соседней вкладке **Variables** создайте repository variable
`DEPLOY_ENABLED` со значением `true`. До появления этой переменной workflow намеренно
пропускает деплой, чтобы не запускаться с незаполненными секретами.

Случайный webhook-секрет можно создать в PowerShell:

```powershell
[Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32)).ToLower()
```

Никогда не записывайте эти значения в файлы репозитория.

### 5. Запустите деплой

После следующего `git push` workflow `.github/workflows/deploy-worker.yml` автоматически:

1. применит схему D1;
2. развернёт Worker;
3. загрузит секреты окружения;
4. зарегистрирует защищённый Telegram webhook.

Прогресс виден во вкладке **Actions → Deploy Telegram bot**. Workflow также можно запустить
кнопкой **Run workflow**. Проверка после деплоя:

```text
https://resale-radar-bot.ВАШ-SUBDOMAIN.workers.dev/health
```

Ожидаемый ответ:

```json
{"ok":true,"service":"resale-radar"}
```

После этого отправьте боту `/start`. Для каждого следующего обновления достаточно обычного
`git push`: GitHub сам развернёт новую версию.

## Использование

Создание фильтра с собственной оценкой цены продажи:

```text
/watch iphone 13 128 | 35000 | 45000 | 5000 | 15
```

Поля: запрос, максимальная цена покупки, ожидаемая цена продажи, минимальная чистая
прибыль и минимальный ROI в процентах.

Автооценка цены продажи:

```text
/watch playstation 5 | 40000 | auto | 5000 | 20
```

Автооценка начнёт выдавать сигналы, когда в базе будет хотя бы `MIN_COMPARABLES` похожих
объявлений. На пустой базе быстрее начать с собственной консервативной цены продажи.

Список и удаление фильтров:

```text
/watches
/delwatch 1
```

## Формат источника объявлений

`LISTINGS_FEED_URL` должен возвращать массив либо объект с массивом `items`:

```json
{
  "items": [
    {
      "external_id": "unique-123",
      "title": "Apple iPhone 13 128GB",
      "price": 32000,
      "url": "https://example.com/listing/123",
      "image_url": "https://example.com/photos/123.jpg",
      "category": "Телефоны",
      "location": "Астрахань",
      "published_at": "2026-11-14T00:00:00+04:00"
    }
  ]
}
```

Те же данные можно отправить вручную командой `/add {JSON}`. Пример лежит в
`example_feed.json`.

`image_url` необязателен: это прямая HTTP(S)-ссылка на фотографию товара.
Выгодные сделки сохраняются в Mini App с фотографией, прибылью и кнопкой объявления.
В Telegram приходит фото с расчётом; если Telegram не может загрузить фото,
бот отправляет текст. Источник проверяется каждые 5 минут при заполненном
`LISTINGS_FEED_URL`. Для ссылок поиска Avito используется отдельный облачный сборщик.

## Облачный сбор Avito без включённого ПК

`Collect Avito deals` в GitHub Actions запускается в 17 минут каждого часа.
Он получает сохранённую ссылку через защищённый `/collector/watches`, открывает
её в Camoufox с виртуальным экраном и передаёт карточки по 5 за запрос.
Проверяется один поиск за запуск; при нескольких поисках используется очередь
по времени последней проверки. Запуски по расписанию ограничены двумя минутами,
ручной запуск — пятью. GitHub может задерживать запуск расписания.

Проверка от 27.11.2026: Camoufox получил 48 и 50 карточек в двух диагностических
запусках; Chrome/patchright получил 48 карточек, но повторный запуск был заблокирован.
Это подтверждает возможность загрузки, а не гарантирует доступность каждого запуска.
Avito может ограничить IP GitHub: такая попытка отображается как ошибка на карточке
фильтра, а не как пустая выдача. Платные прокси, API и решения CAPTCHA не используются.

Сборщик написан отдельно; исходный код AGPL-проекта Case211/avito-watch не перенесён
в приложение. Его браузерный подход проверялся вместе с другими проектами в
`Test more free Avito approaches`. Выдача Avito в Mini App содержит реальные фото;
прибыль отображается только для прошедших расчёт сделок. Telegram получает только
подходящие сигналы; повторы для пары фильтр/объявление отсекаются.

## Как считается сигнал

```text
чистая прибыль = цена перепродажи - цена покупки
                 - комиссия с продажи - фиксированные расходы

ROI = чистая прибыль / цена покупки × 100%
```

При автооценке используется 40-й перцентиль очищенного набора цен аналогов, а не максимум
или простое среднее. Это снижает риск завышенной оценки и лучше соответствует быстрой
перепродаже. Это всё равно только ориентир: дефекты, торг, доставка, налоги и сроки продажи
нужно учитывать отдельно.
